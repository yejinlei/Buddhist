# 第 111 批·白话精译规范（每部一个 worker 端到端）

## 任务目标
为指定的某一部佛经，产出一份**可运行的 Python 构建脚本**，运行后生成
`data/modern-translation/{tid}.json`，并通过项目的严格校验闸门。

## 输入文件
分段原文：`_b111/{tid}.src.txt`
格式：
```
# {tid} 经名 | 译者 | 段数=N
---[0]---
（第 0 段原文）
---[1]---
（第 1 段原文）
...
```
段号从 0 连续到 N-1，共 N 段。

## 参考样例（务必先读）
- 共享构建库：`_b111/lib_mantra.py`
- 标准样例脚本：`_b109/build_t1712.py`（结构照抄它）

## 产出物
`_b111/build_{tid}.py`，结构如下：

```python
# -*- coding: utf-8 -*-
import sys, os
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
from lib_mantra import build

TID = 'tXXXX'
INTRO = ("……经名、译者/作者、卷次归属、全篇内容大意与结构，约 150-400 字，简体……")

TITLES = [
 "段0的小标题",
 "段1的小标题",
 ...   # 长度必须 == N
]

TPL = [
 "段0的白话正文",
 "段1的白话正文",
 ...   # 长度必须 == N
]

if __name__ == "__main__":
    n = build(TID, TITLES, TPL, seeds=('真言曰：',), intro=INTRO)
    print(TID, '段数', n)
```

## 体例硬要求（违反任一条即为不合格）
1. **长度严格相等**：`len(TITLES) == len(TPL) == N`。build 内部会断言，不一致会报错。
2. **每段现代文格式**：build 会自动拼成 `【小标题】【义解】白话正文`。
   - 因此 `TITLES[i]` 只写**不含【】的纯小标题**（如 `序分·六种成就`）。
   - 因此 `TPL[i]` 只写**【义解】之后的正文**（不要自己再加 `【义解】`，也不要加【】前缀）。
3. **【义解】后必须有正文**：不允许 `TPL[i]` 为空，也不允许内容以「【义解】」收尾。
4. **白话用简体中文**，标点全角；引号只用「」『』，**禁止半角引号 `"` `'`**（脚本里的 Python 字符串定界符除外）。
5. **不得改动经文原文**：`original_preview` 由 build 自动从任务文件取，你完全不要碰它。
6. **不编造内容**：白话是该段原文的准确今译；可补必要的科判线索、背景提示，但不得添加原文没有的事实、人名、数字。
7. **失译经**：若 src 首行译者为「失譯」或空，INTRO 中写「失譯，譯人不詳」，不得编造译者。
8. **咒文处理**：凡原文中以「……」包裹的音译咒语（多以「…呪曰：」「…真言曰：」引出），
   在 `TPL` 对应位置写一个 `{@}` 占位符；build 会从原文程序化派生咒文原字并替换。
   一个咒文块写一个 `{@}`。若该段没有咒文块，就不要写 `{@}`。
   若全篇无咒文，`seeds` 保持默认即可（不会命中）。

## 小标题写法
简短概括该段内容，如「序分·六种成就」「劝发菩提心」「释十二因缘」等，简体，不含【】。
