工作根目录：`/home/user/workspace/13511660557912876654/buddhist-ontology`
骨架目录：`data/baihua-tasks/<经号>.json`

## 一、输入
每部经的骨架文件结构：
```
{
 "id": "t0857",
 "title": "大日經略攝念誦隨行法",
 "translator": "唐 不空譯",
 "mode": "baihua",
 "intro": "",
 "sutraPath": "../sutras/t0857.json",
 "translations": [
   {"section": "", "original_preview": "（该段原文，逐字，含换行）", "modern": ""},
   ...
 ]
}
```

## 二、输出
把结果写成 JSON 文件，内容为 **一个对象**，键是经号，值是完整译文文档：
```json
{
  "t0857": {
    "id": "t0857",
    "title": "大日經略攝念誦隨行法",
    "translator": "唐 不空譯",
    "mode": "baihua",
    "intro": "（80-120字简体导语，说明此经性质、译者、主要内容与价值）",
    "sutraPath": "../sutras/t0857.json",
    "translations": [
      {"section": "小标题", "original_preview": "（与骨架逐字一致）", "modern": "【小标题】……【义解】……"}
    ]
  }
}
```

## 三、硬性规则（违反即整部作废）

1. **原文一字不差**：`original_preview` 必须与骨架文件中的对应字段**逐字完全相同**（含所有换行、标点、异体字、音注括注）。禁止改动、禁止截断、禁止拼接。
2. `translations` 的**段数与顺序**必须与骨架完全一致，不得增删。
3. `modern` 必须以 `【小标题】` 开头（与 `section` 字段一致），整段中必须含 `【义解】`，且 `【义解】` 之后还要有正文文字（不能以【义解】结尾，也不能只有【义解】三字）。
4. `modern` 用**简体中文**、**全角标点**（「」『』、。；：），不得出现半角引号 `"` `'`。
5. **咒文/真言照录**：陀罗尼、真言、音译咒句一律**照抄原文用字**（可保留音注括注），另起句用白话说明其作用。禁止凭音重写咒字。
6. **偈颂**：保留原有分句，可用「／」或分行处理，译成白话诗句，不得漏句。
7. **不杜撰**：人名、术语、法数、地名一律以原文为据；原文阙略处就依原文直解，不补造典故或史实。
8. **标题**：`title`、`translator` 保留原文用字（繁体）；`section` 用简体短语（4-12 字，概括该段主旨）。
9. JSON 字符串值内**禁止出现未转义的半角双引号**；需要引用语时用「」。
10. `modern` 的篇幅：白话正文要真正把该段讲清楚，不可只写「（略）」；一般每段 120-400 字。

## 四、白话体例示例（参照已有上线译本）
```
"modern": "【序分·法会因缘】大兴善寺三藏沙门不空奉诏译。我是这样听说的：有一个时候，佛陀住在舍卫国的祇树给孤独园，与大阿罗汉一千二百五十人同住……【义解】本段是经的序分，交代说法的时间、地点与听众……"
```
